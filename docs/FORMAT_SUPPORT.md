# Output support and current boundary

Configuration v1 supports one required output and destination. Configuration v2 supports up to five distinct formats and six explicit output-to-destination mappings, including required/optional outcomes. The form and JSON editor use the same contract; see [mapping and outcome semantics](adr/003-multiple-output-outcomes.md) and [five-format example](../examples/request-all-formats.json). Per-output user retries remain unsupported.

| Format | Implementation                                          | Verification                                                                                            | Limits                                                                   |
| ------ | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| PDF    | Jasper 7.0.3 core + matching PDF module                 | PDFBox text/page checks; browser/cloud SHA-256                                                          | Trusted bundled/registered templates; no password settings                          |
| XLSX   | `JRXlsxExporter` already present in Jasper 7.0.3 core   | ZIP workbook structure, shared strings, numeric cells and absence of formula cells from consumer titles | One worksheet per report page configurable; no macros or external workbook templates |
| CSV    | `JRCsvExporter` in core; UTF-8, CRLF records            | Expected title/rows/amounts; formula-like title cases                                                   | Comma/semicolon/tab configurable; a presentation-grid CSV, not an ETL/data extract API                     |
| DOCX   | Jasper `JRDocxExporter`, hyperlinks disabled            | Document XML, expected rows, escaped title, no external relationships/macros                            | Grid layout; Word visual round-trip and protection settings unverified   |
| HTML   | Jasper `HtmlExporter` into a static `.html.zip` package | Escaped text, content, actual image resource closure, traversal/conflict/size rejection                 | Download/extract locally; no in-app rendering or arbitrary assets        |

The installed 7.0.3 JAR was inspected to confirm exporter and configuration APIs; no additional rendering dependency was needed. Official references: [CSV configuration](https://jasperreports.sourceforge.net/api/net/sf/jasperreports/export/SimpleCsvExporterConfiguration.html), [XLSX sample](https://jasperreports.sourceforge.net/sample.reference/xlsfeatures/README.html). Those online pages can describe newer releases; executable tests validate the pinned version actually used here.

CSV formula escaping is mandatory and overrides template hints. The title, currently the only consumer-controlled text in the trusted sample, is additionally prefixed with an apostrophe before CSV filling, including leading-whitespace cases. That apostrophe is intentionally part of the CSV data. Future data adapters must apply the same policy to all untrusted text cells. XLSX preserves the title as a string while numeric fields remain numeric; consumer parameters do not supply formula properties.

Core records format and MIME type in `report_artifact`; filenames use the UUID and an allowlisted extension. The immutable generated object extension is the delivery v1 format discriminator. Go payload shape and existing PDF fingerprints stay unchanged. Both providers receive the appropriate MIME type. Retained downloads and temporary signed URLs use attachment disposition and the correct extension. Artifact size remains bounded at 10 MiB.

The historical Batch job name `report-pdf-v1` is retained to preserve existing JobInstance restart identity. It now dispatches the exporter selected by the immutable accepted request. Compilation and filling still regenerate the whole document on a rendering retry; a delivery retry uses the retained artifact.

Upgrade all core and delivery workers before enabling new-format submissions. This increment does not support mixed old/new worker binaries: an older renderer cannot interpret a CSV/XLSX request correctly. Stop admission and drain or preserve pending work before rollback; do not downgrade workers while non-PDF jobs remain queued. Core V11 adds explicit job relationships and backfills historical outputs; Go 003 remains the latest Go migration. V11 requires coordinated service upgrades; old core binaries cannot write its required job relationships. Do not edit applied migration checksums or delete accepted records to force a downgrade.

HTML is an `application/zip` attachment containing `index.html` and generated `assets/`. ZIP content and uncompressed package content are each bounded at 10 MiB, with at most 128 resources. Bare HTML and arbitrary ZIP uploads/exports are not accepted. No untrusted templates have been enabled. See [static export policy](adr/004-static-html-and-docx.md) for security boundaries, verified Jasper APIs and deployment compatibility.

V12 adds DOCX/HTML constraints and the compound `.html.zip` suffix; earlier migration checksums remain unchanged. Upgrade all workers before admitting these formats. Normal and signed downloads preserve the package extension. Five-output jobs can create up to 30 delivery tasks across six mappings; the 15-minute job deadline still applies.

Optional `outputOptions` select CSV field delimiters and XLSX page-to-worksheet layout for either request version. Omitted settings retain existing defaults and fingerprints; explicit settings are snapshotted and affect idempotency. Settings for unselected formats are rejected. See [ADR-013](adr/013-output-options.md) for validation, retry and rollout semantics.

Typed trusted-template parameters flow through the shared Jasper fill step. CSV also prefixes custom TEXT values with an apostrophe before export; XLSX keeps literal strings. Exact decimal strings become BigDecimal and dates become the accepted zone's calendar-day start. See [ADR-014](adr/014-typed-template-parameters.md) for type bounds and immutable schema binding.

Trusted templates may now supply immutable named PNG dependencies. Actual embedded image pixels are tested in PDF, XLSX, DOCX and HTML; CSV retains its normal presentation-grid behavior. HTML packages include generated image resources through the existing closure checks. Template source/dependency downloads are separate administrator-only attachments. See [ADR-015](adr/015-template-png-assets.md).

Named JRTX styles are flattened into inline effective styles before Jasper compilation. Actual PDF color pixels and HTML color output are verified, including PNG/style combinations and immutable style revisions. Existing standalone/PNG fingerprints remain compatible. See [ADR-017](adr/017-template-style-assets.md) for supported constant attributes and limits.

Row-scoped JRXML children share the parent's converted parameters and current sales row, including pre-fill CSV text protection. PDF/XLSX/CSV/DOCX/HTML export the filled parent/child document through the existing exporters. Original child files remain separate administrator-only bundle attachments; they are not copied into the generated HTML package. See [ADR-018](adr/018-row-scoped-subreports.md) for closure, compile limits and rollout.

JDBC-backed definitions capture and publish the sales rows during admission. All exporters and delivery retries use the accepted data: fingerprint; reprocessing preserves that fingerprint and import provenance without another JDBC read. No exporter opens a source connection. See [ADR-019](adr/019-jdbc-backed-job-admission.md).

Bounded nested row components preserve typed values, locale/time zone and the current CSV-protected row through each level. All five exporters use the filled parent/child/grandchild document; administrator source archives stay separate from output HTML packages. [ADR-020](adr/020-bounded-nested-subreports.md) defines graph and compiled-material limits.

Small immutable TTF subsets embed in PDF (Identity-H) and package as exact TTF/CSS resources in HTML; generated CSS paths resolve relative to the stylesheet, and output contains no script tags. XLSX/DOCX use original family hints without font installation/embedding, so local substitution and office visual fidelity remain outside the verified boundary. CSV remains presentation-free. Font-bearing text with unsupported characters fails before export. See [ADR-021](adr/021-bounded-truetype-assets.md).

Dataset-scoped subreports placed directly in a summary section receive their immediate parent's full accepted row collection through a fresh cursor. Nested detail components receive one row, and summaries inside those components retain that one-row scope. All five formats share this binding, including existing CSV protection; no export-time JDBC read occurs. See [ADR-022](adr/022-dataset-summary-subreports.md).

XLSX supports optional `xlsxSheetName` alongside worksheet splitting. The first worksheet retains the exact admitted ASCII name; later page worksheets append ` (2)`, ` (3)`, etc., shortening the base to remain within 31 characters. Omission retains existing names. Numeric cells and literal formula-like text retain their existing behavior. See [ADR-023](adr/023-xlsx-worksheet-names.md) for validation and compatibility.

CSV supports optional boolean `csvIncludeBom`. True adds exactly the UTF-8 prefix `EF BB BF`; false omits it, matching the current omitted default. The remaining bytes, quoting, CRLF and formula protection are unchanged. Hashes and delivered bytes include the prefix. Requests without CSV reject this option. See [ADR-024](adr/024-csv-utf8-byte-order-mark.md).
