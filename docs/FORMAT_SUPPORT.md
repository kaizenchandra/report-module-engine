# Output support and current boundary

Configuration v1 supports one required output and destination. Configuration v2 supports up to five distinct formats and six explicit output-to-destination mappings, including required/optional outcomes. The form and JSON editor use the same contract; see [mapping and outcome semantics](adr/003-multiple-output-outcomes.md) and [five-format example](../examples/request-all-formats.json). Per-output user retries remain unsupported.

| Format | Implementation                                          | Verification                                                                                            | Limits                                                                   |
| ------ | ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| PDF    | Jasper 7.0.3 core + matching PDF module                 | PDFBox text/page checks; browser/cloud SHA-256                                                          | Trusted built-in template; no password settings                          |
| XLSX   | `JRXlsxExporter` already present in Jasper 7.0.3 core   | ZIP workbook structure, shared strings, numeric cells and absence of formula cells from consumer titles | No macros, external workbook templates or configurable workbook settings |
| CSV    | `JRCsvExporter` in core; UTF-8, CRLF records            | Expected title/rows/amounts; formula-like title cases                                                   | A presentation-grid CSV; not an ETL/data extract API                     |
| DOCX   | Jasper `JRDocxExporter`, hyperlinks disabled            | Document XML, expected rows, escaped title, no external relationships/macros                            | Grid layout; Word visual round-trip and protection settings unverified   |
| HTML   | Jasper `HtmlExporter` into a static `.html.zip` package | Escaped text, content, actual image resource closure, traversal/conflict/size rejection                 | Download/extract locally; no in-app rendering or arbitrary assets        |

The installed 7.0.3 JAR was inspected to confirm exporter and configuration APIs; no additional rendering dependency was needed. Official references: [CSV configuration](https://jasperreports.sourceforge.net/api/net/sf/jasperreports/export/SimpleCsvExporterConfiguration.html), [XLSX sample](https://jasperreports.sourceforge.net/sample.reference/xlsfeatures/README.html). Those online pages can describe newer releases; executable tests validate the pinned version actually used here.

CSV formula escaping is mandatory and overrides template hints. The title, currently the only consumer-controlled text in the trusted sample, is additionally prefixed with an apostrophe before CSV filling, including leading-whitespace cases. That apostrophe is intentionally part of the CSV data. Future data adapters must apply the same policy to all untrusted text cells. XLSX preserves the title as a string while numeric fields remain numeric; consumer parameters do not supply formula properties.

Core records format and MIME type in `report_artifact`; filenames use the UUID and an allowlisted extension. The immutable generated object extension is the delivery v1 format discriminator. Go payload shape and existing PDF fingerprints stay unchanged. Both providers receive the appropriate MIME type. Retained downloads and temporary signed URLs use attachment disposition and the correct extension. Artifact size remains bounded at 10 MiB.

The historical Batch job name `report-pdf-v1` is retained to preserve existing JobInstance restart identity. It now dispatches the exporter selected by the immutable accepted request. Compilation and filling still regenerate the whole document on a rendering retry; a delivery retry uses the retained artifact.

Upgrade all core and delivery workers before enabling new-format submissions. This increment does not support mixed old/new worker binaries: an older renderer cannot interpret a CSV/XLSX request correctly. Stop admission and drain or preserve pending work before rollback; do not downgrade workers while non-PDF jobs remain queued. Core V11 adds explicit job relationships and backfills historical outputs; Go 003 remains the latest Go migration. V11 requires coordinated service upgrades; old core binaries cannot write its required job relationships. Do not edit applied migration checksums or delete accepted records to force a downgrade.

HTML is an `application/zip` attachment containing `index.html` and generated `assets/`. ZIP content and uncompressed package content are each bounded at 10 MiB, with at most 128 resources. Bare HTML and arbitrary ZIP uploads/exports are not accepted. No untrusted templates have been enabled. See [static export policy](adr/004-static-html-and-docx.md) for security boundaries, verified Jasper APIs and deployment compatibility.

V12 adds DOCX/HTML constraints and the compound `.html.zip` suffix; earlier migration checksums remain unchanged. Upgrade all workers before admitting these formats. Normal and signed downloads preserve the package extension. Five-output jobs can create up to 30 delivery tasks across six mappings; the 15-minute job deadline still applies.
