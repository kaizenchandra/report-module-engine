# Internal delivery contract v1

Transport base: `/backend/api/v1/internal/deliveries`; fixed configured core URL, never caller-supplied. JWT issuer/expiry/audience `report-core` plus `DELIVERY_SERVICE` role required. Browser report users cannot call these endpoints. Service obtains short-lived credentials with client_credentials; no cookie or browser session. TLS mandatory outside loopback development.

`GET /`: up to 20 pending outbox items, oldest first. Fields: `id` UUID, `artifact_id` UUID, `destination_ref` registered identifier, `object_key` sanitized generated path, `sha256` lowercase 64 hex, `size_bytes` bounded positive integer <=10 MiB. Registered destination references match `[a-z][a-z0-9-]{2,63}`; the worker selects its provider adapter independently of the reference name. Prefixes consist of safe slash-terminated segments, at most 200 characters, followed by the artifact UUID and an allowlisted output extension. The immutable task also includes `provider` and `bucket`, which must match that allowlist. No credentials, arbitrary URLs, paths or binaries in messages.

Go stores canonical payload hash and task in its own inbox before upload. Stable ID is the deduplication key. Same ID + changed payload is rejected as a protocol violation. Polling is an outbox relay; records persist until terminal receipt. If acceptance acknowledgement is lost, the next poll is safe.

`GET /{id}/artifact`: streams retained artifact bytes with the recorded MIME type only while task is pending. 404 means task is not available (including cancellation); 410 means storage loss/expiry. Go verifies both byte count and SHA-256 before provider upload. Temporary Go files use a private 0700 scratch directory and 0600 files. Normal completion removes them. Startup/hourly cleanup removes only regular `report-delivery-[0-9]+.pdf` files older than 24 hours; it does not follow symlinks. Core retained artifacts remain outside this cleanup.

`POST /{id}/receipt`: `{status: VERIFIED|FAILED, sha256, version, code, attempts}`. `code` is NONE, UPLOAD_FAILED, UPLOAD_UNVERIFIED, INTEGRITY_MISMATCH, CONFLICT or ARTIFACT_UNAVAILABLE. Attempts 1–5. Receipt persisted in Go before callback; acknowledgement persisted after 204. An identical complete terminal receipt is idempotent; changed receipt fields or checksum return 409. VERIFIED requires code NONE; FAILED requires a failure code. Cancelled jobs acknowledge late receipts but do not change domain status. Java owns job aggregation and audit in the callback transaction. A successful upload never means success until a GET of stored bytes matches expected size/checksum. ETag is not used as checksum. Version may be empty when a provider does not enable versioning.

Go retries at 2, 4, 8 and 16 seconds; each upload cycle has a 60-second deadline. SDK automatic retries disabled to keep one retry budget. Callback retry is independent of upload and cannot regenerate a report. Every S3 retry first compares existing object bytes; matching bytes reconcile a lost receipt, differing bytes fail as conflict. New writes use If-None-Match `*`. Only single-PUT artifacts up to 10 MiB supported, so there are no multipart uploads to abort in this slice.

The implementation uses one database advisory-lock owner per service; Go persists attempts before side effects and reconciles even after a crash on its final upload attempt. Core fences render attempts and uses epoch-specific artifact filenames. GCS uses a does-not-exist precondition and generation-bound byte verification. An UPLOAD_UNVERIFIED receipt means verification was exhausted; an object may still exist. Horizontal throughput scaling remains incomplete; one advisory-lock owner processes deliveries per database. Core artifact volume must survive process restarts. No shared local path is assumed between core and delivery.

## Attempt projection

`POST /{id}/attempts` accepts `{attempts:[{number,phase,status,code,startedAt,endedAt}]}` (maximum six records). Numbers 1–5 are UPLOAD, number 6 is read-only RECONCILE. Status is STARTED, RETRYING, VERIFIED, FAILED or INTERRUPTED. Timestamps are ISO-8601 UTC; STARTED has null endedAt. Codes are NONE, UPLOAD_RETRY, UPLOAD_UNVERIFIED, INTEGRITY_MISMATCH, CONFLICT or WORKER_INTERRUPTED. No raw provider errors or credentials are transmitted.

Go owns durable history. It commits the attempt claim and retry budget together before provider work. Restart marks interrupted upload attempts; final reconciliation can safely repeat without another upload. Core stores a read-only projection for its authorized job API. A terminal projection cannot regress when an earlier STARTED event is replayed. Publishing uses a three-second deadline and never triggers rendering. A complete snapshot must be acknowledged before the final receipt; receipt retry replays the snapshot. Live progress is evidence of operations, not a percentage or a completion guarantee.

Migration ownership remains separate: core Flyway V7 owns the projection, Go migration 002 owns execution history. Deployment allowlists are rechecked for persisted pending tasks after restart; changing a configured bucket cannot redirect an accepted task. Existing terminal receipts can still be acknowledged after such a configuration change.

## Durable cloud controls

`GET /controls` returns up to 20 pending `{id,kind,provider,bucket,objectKey,version,sha256,sizeBytes,artifactId,expiresAt}` operations. CHECK has empty artifact fields and tests bucket metadata access only. SIGN contains the immutable verified delivery identity and checksum. Expiry is fixed by core at acceptance, at most 300 seconds, and is never extended by Go retries. Core admission is owner-scoped, deduplicates unexpired requests for the same resource/version, and permits at most ten new operations per owner per minute.

Go migration 003 owns a separate inbox with immutable payload fingerprints, attempt budget, result and acknowledgement. Provider operations are limited to three attempts with bounded backoff and a 15-second operation deadline. Results persist before callback; lost acknowledgements replay the same result. `POST /controls/{id}/result` accepts `{status:SUCCEEDED|FAILED,code,url}`; identical results are idempotent and conflicting terminal results return 409. The core view is owner-only/no-store and never returns expired URLs. Both stores erase expired result URLs during polling. When workers are stopped, expired URLs can remain in protected database storage, but core never serves them.

CHECK_OK confirms metadata reachability, not write, IAM policy or encryption correctness. SIGN re-verifies bytes and the receipt version before signing. AWS uses SDK SigV4; GCS uses V4 with IAM SignBlob and an explicitly configured signing service account. GCS generation is included in the signed query; S3 versionId is included when available. Unversioned S3 cannot guarantee immutability against out-of-band object replacement; enable bucket versioning when version-pinned downloads are required. Missing GCS signing configuration returns SIGNING_UNAVAILABLE without changing report success.

No URLs or provider exception details enter audit records/logs. Successful URLs are bearer credentials returned only to the owner. `REPORT_ALLOW_EMULATOR_LINKS=false` is the default; the local environment explicitly permits loopback HTTP links and exposes an emulator notice in the UI. S3Mock does not enforce signature expiry. GCS emulator signing is deliberately unavailable; local RSA tests verify GCS signature construction, not cloud IAM enforcement.

## Format extension compatibility

The v1 object-key suffix now allows `.pdf`, `.xlsx` or `.csv`; the other fields and canonical task fingerprint layout remain unchanged. Artifact streaming uses the recorded MIME type. Go derives provider Content-Type from the allowlisted suffix. The 10 MiB size bound applies to every format. Old PDF tasks remain valid. Core migration V9 records `format` for output presentation and defaults existing artifacts to PDF.

## Independent artifact and delivery IDs

Version 2 report configuration can generate several artifacts and map each to several destinations. Task `id` is the delivery identity; `artifact_id` is the byte-stream identity and can differ. Both must be canonical UUIDs. The object key must end with **artifact_id**, not delivery ID, plus the allowlisted extension. Fetch artifacts and publish attempts/receipts using the delivery ID. Payload field order and fingerprint encoding stay unchanged, preserving old inbox entries. Deploy updated workers before enabling multi-output requests. Core alone aggregates all required/optional outcomes under a job lock; Go never marks a job complete. Owner-facing signed links now support explicit delivery IDs.

## DOCX and HTML package extension

Core V12 enables `.docx` and `.html.zip`. The latter is an `application/zip` attachment containing a static HTML report and generated assets. Bare `.html`, generic `.zip` and `.docm` remain invalid task suffixes. The maximum key length is now 245 (200-character prefix + UUID + `.html.zip`). Signed filenames preserve the compound extension; MIME is WordprocessingML for DOCX and application/zip for HTML packages. No payload fields or hash encoding changed. Deploy matching Go/core versions before admitting new formats. Transport tests use synthetic bytes; browser tests verify real Jasper content separately.
